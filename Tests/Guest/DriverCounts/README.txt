R4D count and resident owner qualification
=========================================
Explicit private KVM4 fixtures, image_scope=none; no installed modules or periodic product work.

Tools/Test-DriverCounts.ps1 runs four compositions against actual owner_table,
owner_storage, memory/thread/semaphore owners and resource handle algorithms.
Runtime/heap stand-ins enforce no allocation under the metadata owner and inject
one allocation refusal. These native cases do not claim tasks, DMA hardware or a boot.

Build.ps1 defaults to129 independent ordinary public C R4D containers. Two C
ELFs are built through the canonical SDK manifest project; the shared successful
ELF is selected by exact deterministic repackage/readback against its current
SDK artifact. All identities are then built by the unmodified SDK R4M0 packager,
with distinct module/driver names and current version metadata. No binary header
patching or arbitrary renaming substitutes for container identity. A second
refusal reuses the exact verified refusal ELF after the large owner tables grew.
Generated projects/caches/artifacts belong under Temp and are disposable.

Each successful instance retains192bytes of real owned heap and one semaphore,
checks an actual permit, pins/maps/synchronizes/ends a private4096byte DMA lease,
submits/waits/releases one native Work result129 and creates/joins/releases one
actual generation-bound dedicated thread result229. This is a software fixture:
no GPU mode, display backend, network backend or physical DMA transfer exists.
The display metadata classification exercises software driver inventory records.
It does not advertise real display hardware. Shared DMA pools remain128; leases
are ended before the next instance so the count test does not consume that quota.
The separate resident Work ticket budget remains16.

DC29BAD and DC29END intentionally refuse initialization after acquiring heap and
semaphore, at both ends of the expanded plan. Shutdown verifies retained bytes,
ends acknowledged DMA/heap/semaphore state and checks zero remaining heap work.
Observe is a public C R4X, expects129 active names, actual positive module/runtime
generations, complete inventory beyond128, per-owner completed/released Work,
and unchanged failed query output. It imports only R4SYS/R4DEV.

For a bounded lifecycle qualification the actual private native R4D control may
include/call lifecycle.rs immediately after driver_plan_control(1) in
Rust/driver/driver_policy.rs while constructing only the private test image.
Save the clean file first and use relative module path
../../Tests/Guest/DriverCounts/lifecycle.rs. Freeze/read back that image, then
restore driver_policy.rs and rebuild the normal product. Never commit the
include/call or use its artifact for a product/benchmark. The source remains a
reusable explicit fixture, absent from ordinary compilation. The internal info
result2 means found; the public R4DEV wrapper separately returns1.
The fixture unloads/reloads129 real instances, requires native cleanup ACK,
missing old runtime info, stale old heap owner and newer runtime/resource epoch.
Its assertions are control-flow checks, not a mock shutdown receipt.

Build a private Test image with the normal plan plus these artifacts. Append all
fixture DRIVER directives to a complete CONFIG input exceeding2048bytes. Include
case-insensitive duplicate directives, a real disabled DC29OFF container, PS2
already active, an invalid name and a valid missing module. Preserve normal boot
ordering; disable unrelated SMP selftests only in that image. Observe actual
selected/loaded/active counts and failure classes; line counts alone prove none.
Run Observe through real Terminal/AUTOEXEC or SSH. Keep actual process result,
input/source/artifact identities and compact logs. Product clean build/benchmark
and physical hardware qualification are separate. Remove completed private disk,
generated projects and caches with the canonical test retention helpers.
